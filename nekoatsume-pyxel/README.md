# nekoatsume-pyxel

Pyxel で作る「ねこあつめ」風の放置ゲーム(いまは文字だけの UI)。
[nekoatsume_py](https://github.com/kurookuroda/nekoatsume_py)(コンソール版)のルールを移植しています。
デスクトップ(Windows / macOS / Linux)とブラウザ(スマホ含む)で動かせます。

## リポジトリ構成

```
nekoatsume-pyxel/
├── nekoatsume.py              # Pyxel の UI(起動するスクリプト)
├── game.py                    # ゲームのルール(Pyxel に依存しない)
├── catalog.py                 # アイテム・猫のデータ表(ここに足すだけで増やせる)
├── test_game.py               # ルールのテスト(pytest)
├── tools/ui_smoke.py          # UI のスモークテスト(タップ操作の再現とスクリーンショット)
├── PixelMplus12-Regular.ttf   # 日本語ピクセルフォント 12px(要ライセンス確認・下記参照)
├── PixelMplus10-Regular.ttf   # 同 10px(nekoatsume.py の FONT_PATH / FONT_SIZE で切り替え)
└── README.md
```

`nekoatsume.py` と `game.py` と `catalog.py` とフォントは **リポジトリ直下(フラット)** に置きます
(Pyxel Web Launcher はスクリプトと同じ場所のファイルを読むため)。

## 遊び方

- 起動: `pip install pyxel` のあと `pyxel run nekoatsume.py`
- ブラウザ: `https://kitao.github.io/pyxel/web/launcher/?run=<ユーザー名>.<リポジトリ名>.nekoatsume`
  - スマホでは末尾に `&gamepad=enabled` を付けると仮想ゲームパッドが出ます(このゲームでは使いません。付けなくて構いません)
- 操作: タップ / クリック。1〜5 キーで下のタブを切り替え
  - リスト: ドラッグ(PC はホイールや ↑↓ / PageUp / PageDown / Home / End キー)でスクロール。
    **右端のバーをつかんで動かすと、何百件あっても一気に目的の場所へ行けます**
  - 文章: 1文字ずつ表示されます。表示中にタップすると、その場で全部出ます
  - 文章が枠に収まらないときは、ページに分かれます。右下で ▼ が点滅したら、タップ(または Enter / Space)で次のページへ
  - 長いお知らせ(お宝がたくさん届いたときなど)は、ページ送りのダイアログで出ます。最後のページでタップすると閉じます

流れは、ショップで買う → もちものからおもちゃとエサを庭に置く → 猫が来て、帰るときにさかなを置いていく → 「にわ」で受け取る、です。
エサは300分(5時間)でなくなります。アプリを閉じている間も、実時間のぶんだけ進みます。

## 用意するファイル

**PixelMplus12-Regular.ttf** は [PixelMplus](https://github.com/itouhiro/PixelMplus) の配布ページから取得してください。
再配布する場合は、配布元のライセンスに従い、ライセンス文書も同梱してください。
フォントがなくても動きますが、日本語が表示されません。

## セーブ

`pyxel.user_data_dir()` が返すフォルダの `save.json` に、操作のたびと1分ごとに自動保存します。
ブラウザ版で、ページを閉じても残るかどうかは、まだ確認できていません(下記)。

## 開発

```
pip install pyxel pytest
pytest -q                          # ゲームのルール(32 件。猫1000匹・商品600種類の規模テストを含む)
python3 tools/ui_smoke.py          # UI(画面のない Linux では xvfb-run を付ける。tools/ui_smoke.py 冒頭を参照)
pyxel package . nekoatsume.py      # 複数ファイルを .pyxapp にまとめる(Launcher の ?play= や app2html で使える)
```

## 猫・アイテムを増やす

`catalog.py` の表に1行足すだけです(コードの変更は要りません)。

```python
# おもちゃ: (ID, 名前, 価格, 通貨, 庭で使うマス数, 説明)
("bell_toy", "鈴のおもちゃ", 40, "s", 1, "ちりんと鳴る、小さな鈴。"),
# 猫: (ID, 名前, 紹介文, お宝)   個性を変えるときは、末尾に {"strength": 6, "entry_chance": 0.05} のように足す
("mike", "ミケ", "三毛のおっとりした猫", "小さな鈴"),
```

ID は英数字とアンダースコアで、セーブデータのキーになるので、あとから変えないでください。
読み込むときに、ID の重複・庭に入らない大きさのおもちゃ・種別のないアイテムをチェックします(`ValueError`)。

猫やアイテムが増えても困らないように、次の作りにしてあります。

- **図鑑は「出会った順」**に並びます。猫がはじめて庭に来たとき、図鑑の中での位置が決まります(`met_order`)。
  未発見の猫は「？？？ あと◯匹」の1行にまとめるので、一覧は長くなりません。
- **セーブに入る猫は、出会った猫だけ**です(未発見の猫は状態を持ちません)。1000匹でも、保存の大きさは出会った分で済みます。
- **プロフィールの伏せ字は、本当の文と同じ長さ**(「？」×文字数)で組みます。お宝が明かされても、行の数や位置が変わりません。
- **ショップ**は、種別タブ(3つ以上なら ◀ ▶ でめくる)・絞り込み(すべて / 買える / 未所持)・並べ替え(標準 / 安い順 / 高い順)で探せます。
  見えている行だけを描くので、商品が何千あっても軽く、条件や持ち物が変わったときだけ並べ直します。
- 来訪判定は、エサとおもちゃがあるときだけ行い、猫が多いときは順番を混ぜます(先頭の猫ばかりが席を取らないように)。
  猫1000匹・30日ぶんの離席から復帰しても、0.2秒ほどで済みます(実測)。

## コンソール版からの意図的な変更

1. 庭の容量判定を `<` から `<=` にしました(元は6マスあっても5マスしか使えませんでした)。
2. 大型キャットハウスをサイズ 7 → 6 にしました(元は置けず、エサ扱いで購入されていました)。
3. アイテムの種別(おもちゃ / エサ)を、サイズの閾値ではなく `kind` で判定します。
4. 内部IDと表示名を分けました(セーブデータのキーは `rubber_ball` のようなID)。
5. おもちゃを庭から外すと、遊んでいた猫はさかなを置いて帰ります(元は無報酬で追い出していました)。
6. エサを置き換えるとき、残りが捨てられることを確認するダイアログを出します。

猫の来訪率・滞在時間・報酬の計算は元と同じです。元の `update.tick` で測った経済
(おもちゃ5個・エサ常時で、銀 約112/時、来訪 約9回/時、滞在 平均約18分)と一致することを、`test_game.py` で確認しています。
以前のコンソール版の `data.json` は引き継げません(移行処理は未実装)。

## 動作確認の状況

確認済み(Linux + 仮想ディスプレイ):

- ゲームのルール(pytest 32 件)と、猫1000匹・商品600種類での動作・速度・セーブの大きさ

- スクロールバーのドラッグ(猫300匹・商品600件)と、種別タブが多いときの ◀ ▶

## これから

- 猫ごとの個性(好物のおもちゃ、来訪率、押し出しの強さ)と、図鑑の充実
- 絵(スプライト)の追加
- 経済の調整(使い道のない銀の解消)

- 猫が増えたときの来訪ペース: いまは猫ごとに「1分で10%」で来訪を判定するので、猫が数十匹以上になると、庭がいつも満席になり、
  収入が頭打ちになります。猫ごとの「珍しさ」に応じた重みづけで、庭全体の来訪回数を一定に保つ設計への切り替えが必要です。
